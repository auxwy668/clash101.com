## Clash Verge Rev 界面概览

启动 Clash Verge Rev 后，系统托盘会出现 Clash 图标。右键图标可以快速执行常用操作，但更推荐你双击打开主面板进行详细配置。

主面板分为以下几个核心区域：

### 左侧导航栏

- **概览（Dashboard）**：显示当前连接状态、流量统计和最近日志
- **代理（Proxies）**：节点管理核心页面，用于选择节点和配置策略组
- **规则（Rules）**：查看和管理分流规则
- **订阅（Profiles）**：管理订阅链接，导入/更新节点
- **连接（Connections）**：查看当前活跃的代理连接
- **日志（Logs）**：实时查看 Clash 运行日志，排查问题
- **设置（Settings）**：应用配置、外观、内核等全局设置

### 顶部状态栏

顶部显示 Clash 的运行状态：代理开关、TUN 模式开关、当前流量速率（上行/下行）、已运行时长等关键信息。绿色表示一切正常，红色表示存在异常。

## 订阅管理：从导入到自动更新

订阅管理是 Clash Verge Rev 最基本也最重要的功能。一个好的订阅管理习惯能省去你大量手动维护节点的时间。

### 导入订阅链接

1. 打开 Clash Verge Rev 主面板
2. 点击左侧"订阅"标签
3. 在页面顶部的输入框中粘贴你的订阅链接（从机场获取）
4. 点击右侧的"导入"按钮
5. Clash 会自动从链接下载配置文件和节点列表

导入成功后你会看到订阅卡片，包含以下信息：
- **订阅名称**：可自定义，方便区分多个机场
- **节点数量**：该订阅包含的节点总数
- **最后更新时间**：上次同步节点的时间
- **过期时间**：订阅链接的有效截止日期

### 管理多个订阅

如果你有多个机场账号，Clash Verge Rev 支持同时导入多个订阅。所有机场的节点会合并在一起，你可以统一管理：

- 点击"订阅"页面的"添加"按钮，导入第二个订阅链接
- 每个订阅独立更新，互不影响
- 在"代理"页面，不同订阅的节点会自动按来源分组

> 💡 **实用技巧**：给每个订阅取一个有意义的名字，比如"主用机场 - 香港专线"、"备用机场 - 日本"，这样在节点多的时候不会混淆。

### 手动与自动更新订阅

机场的节点列表会动态变化——旧节点下线、新节点上线、IP 地址变更等。因此定期更新订阅非常重要：

**手动更新**：
- 在订阅卡片上点击"更新"按钮（圆形箭头图标）
- 等待几秒钟，Clash 会从订阅链接重新拉取节点列表
- 更新完成后节点数量和内容会实时刷新

**自动更新**：
1. 进入"设置" → "订阅设置"
2. 找到"自动更新间隔"选项
3. 设置更新频率（推荐 360 分钟 = 每 6 小时一次）
4. 开启"启动时自动更新"

### 订阅链接失效怎么办？

如果你点击更新后提示"更新失败"或"请求超时"，按以下顺序排查：

1. **链接过期**：登录机场后台，查看订阅链接是否过期，可能需要手动续期
2. **网络不通**：在不开代理的情况下尝试访问订阅链接（浏览器打开），确认链接本身可用
3. **机场故障**：联系机场客服确认服务是否正常
4. **Clash 版本**：更新 Clash Verge Rev 到最新版本

## 节点管理：分组、选择与测试

节点管理是日常使用最频繁的操作。一个管理得当的节点列表能让你在不同场景下快速切换最优线路。

### 节点分组逻辑

Clash Verge Rev 会自动按以下维度对节点分组：

- **按协议分组**：SS、SSR、VMess、Trojan、Hysteria 等
- **按地区分组**：🇺🇸 美国、🇯🇵 日本、🇭🇰 香港、🇸🇬 新加坡、🇹🇼 台湾等
- **按策略分组**：自动选择、手动选择、故障转移等
- **按来源分组**：不同订阅来源的节点分开显示

在"代理"页面，每个分组是一个可折叠的卡片，展开后可以看到该组的所有节点。每个节点旁边显示以下信息：

- **节点名称**：机场自定义的节点标识
- **延迟（ms）**：绿色表示低延迟（<200ms），黄色中等（200-500ms），红色高延迟（>500ms）或超时
- **流量信息**：部分节点会显示已用流量/总流量

![Clash Verge Rev 节点分组与选择](/images/clash101/clash-verge-nodes-group.jpg)

### 延迟自动测速

延迟测速帮你快速找到当前最快的节点：

1. 在"代理"页面，右键任意节点
2. 选择"延迟测试"
3. Clash 会对所有节点逐一发送测试请求
4. 等待几秒到几十秒（取决于节点数量），所有节点的延迟数据会更新

你也可以点击分组卡片标题右侧的测速图标，只测试该组内的节点。这个功能在节点数量多、全量测试太慢时非常实用。

### 手动选择节点

最基础的使用方式：

1. 打开"代理"页面
2. 在"手动选择"或"🔰 代理"策略组下，点击你想使用的节点
3. 当前选中的节点会高亮显示，同时系统托盘图标颜色变化表示连接已切换
4. 所有走代理的流量都会经过这个节点

### URL 延迟测试（更精准）

普通的延迟测试只测 TCP 连接延迟，URL 延迟测试则模拟真实请求：

1. 在"设置" → "连接设置"中，将延迟测试 URL 改为 `https://www.gstatic.com/generate_204`
2. 这个 URL 是 Google 的连通性检测地址，测试结果更贴近实际使用体验
3. 你也可以换成自己常用的目标网址

### 节点排序与筛选

当你有几十甚至上百个节点时，以下技巧能帮你快速定位：

- **按延迟排序**：点击延迟列标题，节点按延迟从低到高排列
- **按名称搜索**：在搜索框输入关键词（如"香港"、"日本01"），快速筛选
- **收藏节点**：对常用的节点右键 → 收藏，它们会出现在独立的收藏分组中

## 策略组：智能选择节点的进阶玩法

策略组是 Clash Verge Rev 最强大的功能之一。它让节点选择不再依赖手动操作，而是根据预设策略自动完成。

### 策略组类型详解

Clash Verge Rev 支持以下策略组类型：

| 策略组类型 | 功能 | 适用场景 |
|-----------|------|---------|
| **手动选择（Select）** | 手动从候选节点中选择一个 | 日常使用，精准控制 |
| **自动选择（URL-Test）** | 自动选择延迟最低的节点 | 追求速度，不需要固定地区 |
| **故障转移（Fallback）** | 首选节点不可用时自动切换备用 | 保证连接不中断 |
| **负载均衡（Load-Balance）** | 在多个节点间轮询分配流量 | 分散流量，避免单节点过载 |

### 配置策略组实战

以"故障转移"策略组为例，假设你的配置如下：
- 首选节点：日本 01（低延迟）
- 备用节点：新加坡 01、香港 02、美国 01

当日本节点正常时，所有流量走日本。一旦日本节点超时或不可用，Clash 自动切换到新加坡节点；新加坡也挂了就切香港，以此类推。这种机制确保了代理连接的高可用性。

配置方法：
1. 右键"代理"页面的策略组标题
2. 选择"编辑"或"修改类型"
3. 选择"Fallback"（故障转移）
4. 按优先级排列候选节点（拖拽排序）
5. 保存配置

### 策略组在规则中的应用

策略组最大的价值体现在和规则的配合使用。比如你可以这样配置：

```
# 流媒体分组走专门的流媒体节点
策略组：🎬 流媒体 → 类型：Select → 节点：Netflix专线、Disney+专线、YouTube专线

# 规则绑定
DOMAIN-SUFFIX,netflix.com,🎬 流媒体
DOMAIN-SUFFIX,disneyplus.com,🎬 流媒体
DOMAIN-SUFFIX,youtube.com,🎬 流媒体
```

这样当你看 Netflix 时自动走 Netflix 专线，看 YouTube 时走 YouTube 专线，普通网页走默认代理节点，互不干扰。

## 规则管理：自定义你的分流策略

Clash 的规则系统决定了哪些流量走代理、哪些直连。Clash Verge Rev 内置了一套通用规则，但你可以根据自身需求自定义。

### 规则语法速查

```
# 域名匹配
DOMAIN,example.com,PROXY           # 精确匹配 example.com
DOMAIN-SUFFIX,google.com,PROXY     # 匹配 *.google.com
DOMAIN-KEYWORD,google,PROXY        # 匹配含 google 的域名

# IP 匹配
IP-CIDR,1.1.1.0/24,DIRECT          # 匹配 IP 段
GEOIP,CN,DIRECT                     # 中国 IP 直连

# 进程匹配（Windows/macOS）
PROCESS-NAME,telegram.exe,PROXY    # Telegram 走代理

# 兜底规则
MATCH,PROXY                         # 以上都不匹配的全部走代理
```

### 添加自定义规则

1. 打开"规则"标签页
2. 点击页面底部的"添加规则"
3. 选择规则类型（DOMAIN-SUFFIX 最常用）
4. 输入目标域名（如 `openai.com`）
5. 选择策略：直连（DIRECT）、代理（PROXY）、拒绝（REJECT）或指定策略组
6. 点击确认，规则立即生效

### 规则优先级

规则是**从上到下**匹配的，排在前面的规则优先级更高。这意味着：
- 特殊规则放在前面（如 `DOMAIN,api.openai.com,PROXY`）
- 通用规则放在后面（如 `GEOIP,CN,DIRECT`）
- 兜底规则 `MATCH` 必须放在最后一行

常见的调优操作：如果你发现某个应该走代理的网站走了直连（或者反过来），去"日志"标签查看该域名的实际匹配结果，然后调整规则顺序。

## 连接管理与流量监控

"连接"标签页是你排查网络问题的重要工具。

### 查看活跃连接

打开"连接"页面，你会看到一个实时更新的连接列表。每一行代表一个活跃的网络连接，包含以下信息：

- **目标地址**：正在访问的域名或 IP
- **来源进程**：发起连接的应用（需要开启进程识别）
- **规则匹配**：该连接命中了哪条分流规则
- **代理链**：流量经过了哪个代理节点
- **上传/下载**：该连接的实时速率

### 使用连接页排查问题

**场景 1：某个网站打不开，不知为什么**

1. 访问目标网站
2. 快速切换到 Clash 的"连接"页面
3. 在列表中找到目标域名
4. 检查"规则匹配"列——如果显示 `DIRECT` 但你希望走代理，说明规则配错了
5. 检查"代理链"列——如果显示代理节点但连接失败，说明节点有问题

**场景 2：网速慢，想知道哪个应用在占用带宽**

1. 打开"连接"页面
2. 按"下载"列排序，看哪个连接的流量最大
3. 找到来源进程，决定是否需要限制或关闭

### 关闭特定连接

如果某个连接卡住或不想让它继续，可以右键该连接 → "关闭连接"。这在切换节点后清理残留连接时特别有用。

## 高级设置：性能优化与安全配置

### 内核设置优化

在"设置" → "内核设置"中，有一些影响性能和兼容性的关键选项：

- **混合端口（Mixed Port）**：默认 7890。Clash 监听该端口接收 HTTP 和 SOCKS5 代理请求。除非与其他软件端口冲突，一般不需要改动。
- **允许局域网连接**：开启后同一 Wi-Fi 下的其他设备（手机、平板）也能通过你的 Clash 上网。适合在公司或家里共享代理的场景。
- **IPv6**：如果你的网络支持 IPv6 且代理节点支持，可以开启。否则建议关闭以避免连接问题。

### DNS 设置

Clash 的 DNS 模块能防止 DNS 泄漏——即你的 DNS 查询被本地运营商看到。正确配置 DNS 是保护隐私的关键一步：

1. 进入"设置" → "DNS 设置"
2. 确保"启用 DNS"已开启
3. DNS 服务器建议使用：
   - `https://dns.google/dns-query`（Google DNS over HTTPS）
   - `https://cloudflare-dns.com/dns-query`（Cloudflare DNS over HTTPS）
   - `223.5.5.5`（阿里 DNS，用于国内域名解析加速）
4. 开启"DNS over HTTPS"和"Fake-IP"模式（Fake-IP 可以提高 DNS 解析速度）

> ⚠️ **注意**：DNS 设置不当可能导致部分网站无法访问。如果你不确定如何配置，保持默认设置即可。

### 外观与操作习惯

Clash Verge Rev 支持以下个性化设置：

- **主题模式**：亮色 / 暗色 / 跟随系统
- **语言**：中文 / English
- **启动行为**：开机启动、静默启动（不弹出窗口）、最小化到托盘
- **快捷键**：自定义全局快捷键快速开关代理

## 常见问题与故障排查

<details>
<summary><strong>Q1：订阅导入后节点列表为空，怎么办？</strong></summary>

排查步骤：
1. 确认订阅链接完整，没有多复制或少复制字符
2. 在浏览器中直接打开订阅链接，检查是否能正常访问
3. 如果浏览器也打不开，说明订阅链接本身有问题——联系机场客服
4. 如果浏览器能打开但 Clash 不能，检查 Clash 版本是否过旧（建议更新到最新版）
5. 尝试在"订阅"页面点击"强制更新"，而非普通更新
</details>

<details>
<summary><strong>Q2：为什么延迟测速显示超时，但节点仍能使用？</strong></summary>

延迟测试使用的是 TCP 连接测试，而代理流量可能走的是 UDP 或其他协议。节点能使用但延迟显示超时，通常是因为：
- 节点的延迟测试端口被防火墙拦截
- 节点使用了非标准代理协议

**解决方案**：在"设置"中切换延迟测试 URL，或者改用 URL 延迟测试（发送真实的 HTTP 请求）。只要节点能正常上网，延迟显示超时可以忽略。
</details>

<details>
<summary><strong>Q3：开启 TUN 模式后，部分国内应用无法联网？</strong></summary>

TUN 模式下所有流量都经过 Clash，如果规则配置有问题，国内应用可能被错误地代理到了海外节点。

解决方法：
1. 检查规则配置，确保 `GEOIP,CN,DIRECT` 规则存在
2. 在"规则"页面添加特定应用的直连规则：
   ```
   PROCESS-NAME,WeChat.exe,DIRECT
   PROCESS-NAME,dingtalk.exe,DIRECT
   ```
3. 如果是个别网站问题，临时关闭 TUN 模式，使用系统代理即可
</details>

<details>
<summary><strong>Q4：如何让特定网站（如 ChatGPT）强制走某个固定节点？</strong></summary>

有两种方法：

**方法一：策略组 + 规则**
1. 创建一个新的策略组（如"🤖 AI 服务"），只包含你想用的节点
2. 在"规则"中添加：
   ```
   DOMAIN-SUFFIX,openai.com,🤖 AI 服务
   DOMAIN-SUFFIX,chatgpt.com,🤖 AI 服务
   DOMAIN-SUFFIX,claude.ai,🤖 AI 服务
   ```

**方法二：直接规则**
如果你不需要策略组，直接指定节点名：
```
DOMAIN-SUFFIX,openai.com,🇺🇸 美国01
```
</details>

<details>
<summary><strong>Q5：Clash Verge Rev 内存占用越来越高怎么办？</strong></summary>

长时间运行后 Clash 的内存占用确实可能上升，这是日志累积和连接缓存导致的：

1. 定期重启 Clash（建议每 2-3 天重启一次）
2. 在"设置"中降低日志级别：将"日志级别"从 `debug` 改为 `info` 或 `warning`
3. 关闭不必要的功能，如"流量统计记录"
4. 更新到最新版本——新版本通常会修复内存泄漏问题
</details>

<details>
<summary><strong>Q6：多个策略组之间的节点可以共享吗？</strong></summary>

可以。Clash Verge Rev 的节点和策略组是多对多关系。同一个节点可以同时出现在"默认代理"、"流媒体"、"AI 服务"等多个策略组中。

但需要注意：不同策略组选择同一个节点时，该节点的流量会叠加。如果你流量有限，建议为高流量场景（如 YouTube 4K）使用独立节点，避免影响日常浏览体验。
</details>

<details>
<summary><strong>Q7：Clash Verge Rev 和 Clash for Windows 有什么区别？</strong></summary>

- **Clash for Windows（CFW）** 是 Clash 最早的 Windows 图形客户端，由 Fndroid 开发，已于 2023 年停止更新。
- **Clash Verge Rev** 是 CFW 的继任者，基于更现代的 Clash Meta 内核，界面更美观、功能更丰富，目前仍在积极维护。

如果你还在使用 CFW，强烈建议迁移到 Clash Verge Rev。迁移很简单：导出 CFW 的订阅链接 → 在 Clash Verge Rev 中导入 → 完成。配置文件和规则可能需要手动迁移，但大部分功能都有对应的替代方案。
</details>
